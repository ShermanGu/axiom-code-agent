# Axiom v0.5.0 — P0-2 durable execution and recovery

Status: Completed

Priority track: P0-2

## Outcome

Agent runs survive process boundaries as inspectable SQLite checkpoints and can continue from known
model/tool state without silently replaying an operation whose outcome is uncertain.

## Scope

- [x] Persist runs, plans, steps, attempts, model turns, and tool calls with stable IDs.
- [x] Add `axiom runs`, `runs show`, `runs export`, and `axiom resume`.
- [x] Restore completed steps and known tool outputs when resuming.
- [x] Block automatic recovery when an interrupted tool may already have caused side effects.
- [x] Distinguish failed, cancelled, interrupted, skipped, and blocked lifecycle states.
- [x] Persist sanitized EventBus events in SQLite while retaining `.axiom/events.jsonl`.
- [x] Account separately for Planner, Executor, and Finalizer calls, tokens, failures, and latency.

## Acceptance

- [x] Unit tests pass on Ubuntu and Windows with Python 3.11 and 3.14.
- [x] A deterministic interruption test resumes after a completed tool without replaying it.
- [x] An uncertain tool outcome blocks recovery unless replay is explicitly authorized.
- [x] Ruff, Mypy, bytecode compilation, core Eval, and wheel inspection pass.
- [x] The built wheel reports Axiom 0.5.0 and contains the packaged evaluation suite.

## Deferred

- Transactional file patches, rollback, and agent-owned change tracking remain P0-3.
- General retry deduplication and side-effect-aware retry budgets remain P0-6.
- Cross-process leases and concurrent writers are not yet supported; one active Axiom process should
  own a workspace run database at a time.
