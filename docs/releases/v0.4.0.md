# Axiom v0.4.0 — Evaluation foundation

Status: Completed

Priority track: P0-1

## Outcome

A maintainer can run a deterministic offline suite against the real Agent runtime and receive a
machine-readable regression report before changing execution, persistence, or mutation semantics.

## Scope

- [x] Add a versioned JSON evaluation-suite format.
- [x] Run every case in an isolated temporary workspace.
- [x] Exercise the real planner, Agent loop, ToolRegistry, memory, events, and finalizer.
- [x] Add eight initial regression cases.
- [x] Report duration, model calls, tool calls, token estimates, changed files, and failures.
- [x] Expose the suite through `axiom eval`.
- [x] Add a unit-test gate for the core suite.
- [x] Add exact, allowed, and forbidden file-change assertions.
- [x] Add command exit-code and verification-evidence scenarios.
- [x] Add Windows/Linux CI execution, report artifacts, and a committed baseline summary.
- [x] Isolate evaluations from local Axiom configuration and package the default suite.

## Acceptance

- [x] `python -m axiom_agent.cli eval` reports `8/8 passed`.
- [x] `python -m unittest discover -s tests -v` passes on Windows and Linux CI.
- [x] The report at `.axiom/evals/core-latest.json` uses schema version 1.
- [x] Python 3.11/3.14 tests plus Ruff and Mypy pass in the merge PR.

## Deferred

- P0-2 durable Run/Step/Turn/ToolCall persistence is targeted after the baseline is retained.
- P0-3 transactional patches and rollback depend on P0-2 ownership and checkpoint identifiers.
- Live-model quality suites require separate credential, cost, and non-determinism policies.
